- **`apps/api/scripts/set-restricted-password.ts`** — sets `rebound_restricted`'s login password out-of-band (never committed), and a matching `RESTRICTED_DATABASE_URL` wired into `.env` / `.env.example` / `apps/api/src/db.ts` (a second `pg.Pool`, undefined until the env var is set).

- **`documents/INGEST_RUNBOOK.md`** — the ingest order of operations, written from what's already documented in this repo.
- **`documents/DATA_MODEL.md` and `documents/IMPLEMENTATION_TODO.md`** updated to reflect actual current state — both had gone stale (still describing "exactly one table" and Prisma, which are no longer true).

Bug caught and fixed along the way: the first migration attempt failed because RLS policies referenced `rebound_restricted` before the role was created later in the same file — Postgres needs the role to exist first. node-pg-migrate's per-migration transaction rolled back cleanly; fixed the ordering and reran.

Also cleaned up: a stray Docker Postgres container from the pre-rewrite architecture was still running locally and `.env`'s `DATABASE_URL` was still pointing at it, which is why the first migration attempt hit `role "anon" does not exist` — that role only exists in real Supabase. Stopped and removed the container; `.env` now points at the real Supabase project.
